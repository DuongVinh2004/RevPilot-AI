## 1. Traceability Methodology and Status Classification

This matrix tracks the end-to-end lifecycle lineage from canonical business requirements and invariants through design specifications, architectural decisions, physical implementation artifacts, verification test suites, and empirical evidence artifacts.

Status Classification Vocabulary:
- **Designed**: Formally codified in canonical specification documents (docs/).
- **Implemented**: Physically implemented in source code (packages/backend/).
- **Tested**: Verified by an executed, retained automated test artifact. A referenced test path or static source inspection is not a Tested claim.
- **Evidenced**: Empirical operational evidence generated and verified on live infrastructure (execution/evidence/).
- **Reviewed**: Reviewed and approved by the designated domain lead.
- **Accepted**: Officially signed off by the platform approver (Dương Vinh).
- **Pending**: Downstream execution gate not yet satisfied.
- **Blocked**: Progress stopped by an upstream dependency or open decision.
- **Not Applicable**: Not required for the declared tier or stage.
- **[PROSPECTIVE]**: Indicates that a referenced implementation path or test suite represents a planned/future artifact not currently present or executed in the repository; it is not implementation or verification evidence.
