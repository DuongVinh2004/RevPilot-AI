## Input/output and validation

INPUT: Typed constructor arguments or validated dictionaries.
OUTPUT: Immutable domain entity instances.
INVALID INPUT:
- Missing `tenant_id` -> raises `ValidationError`.
- Negative money amount -> raises `ValidationError`.
- Inconsistent timestamps (`effective_to < effective_from`) -> raises `ValidationError`.
- `total_cents != subtotal_cents + tax_cents + shipping_cents` -> raises `ValidationError`.

## Security contract

AUTHENTICATION: Required; calling context must provide authenticated Principal.
AUTHORIZATION: Server-side check.
TENANT: Mandatory tenant ownership on all entities (`INV-TEN-001`).
PII: `Customer.name`, `Customer.email`, `SupportTicket.transcript_text` classified as PII; masked in logging.
SECRET ACCESS: Prohibited.
EXTERNAL ACTION: Prohibited.
DEFAULT: DENY.

---

## Operational behavior

RETRY: Non-retryable on validation failure.
TIMEOUT: Pure compute; <1ms per entity validation.
IDEMPOTENCY: Governed by `dedup_key`.
LOGGING: Structured logging on validation failures; payload PII redacted.
METRICS: Counter `canonical_entities_validated_total{entity_type=...}`.
FAILURE BEHAVIOR: Fail-closed; return `Result.err(CanonicalValidationError)`.
ROLLBACK/COMPENSATION: Pure in-memory; no side effects.
