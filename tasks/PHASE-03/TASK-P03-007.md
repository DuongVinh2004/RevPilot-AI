## Objective and rationale

OBJECTIVE: Implement the customer support ticket normalization pipeline, PII/secret scrubbing filters, deduplication and out-of-order handling, and prompt injection isolation boundaries in `packages/backend/src/revpilot/modules/tickets/`.

BUSINESS RATIONALE: Support tickets contain vital customer signals during revenue and delivery incidents, but represent untrusted external text (`INV-SEC-002`, `SEC-004`). Ingested ticket text must be sanitized of PII (`INV-PRV-001`, `NFR-PRV-001`), shielded against prompt injection attacks, and transformed into cited evidence objects without granting authority.

ARCHITECTURAL OWNER: AI Platform Architecture / NLP
ARCHITECTURAL CONTEXT: Conforms to `docs/06-agent-platform/TICKET-INTELLIGENCE-SPEC.md` §1–§7, `docs/18-data-governance/DATA-GOVERNANCE.md`, and `ADR-0004`.

## Symbol-level contract

MUST EXPORT/DEFINE:
- `revpilot.modules.tickets.domain.models`:
  - `CanonicalTicket(BaseModel)`: `ticket_id`, `tenant_id`, `source_system`, `version`, `customer_id`, `created_at`, `updated_at`, `status`, `priority`, `category`, `subject_masked`, `body_masked`, `injection_risk_score`, `is_quarantined`, `content_digest`.
- `revpilot.modules.tickets.services.dlp_scrubber`:
  - `scrub_pii_and_secrets(text: str) -> str`:
    Redacts PANs, SSNs, raw credentials, high-entropy secrets, and masks customer emails/phones.
- `revpilot.modules.tickets.services.normalizer`:
  - `normalize_ticket_text(raw_text: str) -> str`:
    Performs Unicode NFC normalization, removes terminal escape sequences and null bytes.
- `revpilot.modules.tickets.services.evidence_extractor`:
  - `extract_ticket_evidence(tickets: List[CanonicalTicket], investigation_id: UUIDv7) -> List[EvidenceRecord]`

MUST NOT:
- Allow unredacted credit card or secret tokens into `body_masked` (`INV-PRV-001`).
- Allow ticket text to modify prompt instructions or trigger agent tools (`INV-SEC-002`).

## Input/output and validation

INPUT: Raw ticket payload from external ticketing feed or synthetic benchmark.
OUTPUT: Sanitized `CanonicalTicket` and extracted `EvidenceRecord` items.
VALIDATION RULES:
- Reject events where `updated_at < stored_record.updated_at` from overriding canonical state.
- Score injection risk; flag `is_quarantined = True` if score > 0.85.

## Security contract

AUTHENTICATION: Required on ingestion adapter.
AUTHORIZATION: Scope `tickets:ingest`.
TENANT: TenantContext strictly enforced.
PII: Scrubbed and masked at source.
SECRET ACCESS: Strictly prohibited.
EXTERNAL ACTION: Disabled.
DEFAULT: DENY.

## Operational behavior

RETRY: Ingestion webhook retries handled via idempotency key `(tenant_id, source_system, ticket_id, version)`.
TIMEOUT: 5,000 ms processing timeout.
IDEMPOTENCY: Guaranteed by composite natural key.
LOGGING: Masked ticket events only.
METRICS: `tickets_ingested_total`, `tickets_pii_redacted_count`, `tickets_quarantined_count`.
FAILURE BEHAVIOR: Drops or quarantines poisoned records.
