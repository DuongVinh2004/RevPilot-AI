## Input/output and validation

INPUT: Typed provisioning payload (`slug: str`, `tier: SubscriptionTier`, `admin_email: str`).
OUTPUT: Initialized `TenantId` with state `PROVISIONING` transitioning to `ACTIVE` upon verification.
INVALID INPUT: Empty slug, malformed email, or missing dual approval token for deletion.
VALIDATION RULES: Slugs match `^[a-z0-9-]{3,64}$`. Deletion strictly blocked if `legal_hold_active == True`.
STATE TRANSITIONS: Conforms to `TENANT-OPERATIONS-SPEC.md` §2.

## Security contract

AUTHENTICATION: Required (`platform_admin` or `tenant_admin`).
AUTHORIZATION: Deny-by-default server-side check.
TENANT: Explicit tenant scoping; deletion propagates strictly within `tenant_id`.
PII: Prohibited in logs and audit events; export package encrypted.
SECRET ACCESS: Prohibited; secrets are referenced by ID only.
EXTERNAL ACTION: Prohibited.
DEFAULT: DENY.

## Operational behavior

RETRY: Exponential backoff on transient database errors (max 3 retries).
TIMEOUT: Provisioning saga timeout 300 seconds; API timeout 15 seconds.
IDEMPOTENCY: Checkpoint key `prov_{tenant_id}_{schema_version}`.
LOGGING: Structured JSON logging with `revpilot.tenant_id`.
METRICS: `tenancy.lifecycle.status_gauge`, `tenancy.deletions.total`.
FAILURE BEHAVIOR: Provisioning failure halts, rolls back allocated resources, transitions to `PROVISION_FAILED`.
ROLLBACK: Cascade deletion is irreversible; requires dual human approval (`INV-ACT-003`).
