## Input/output and validation

INPUT: Authorization code, PKCE `code_verifier`, signed `id_token` JWT.
OUTPUT: Verified `PrincipalContext` bound to server-derived `TenantId` with assigned roles.
INVALID INPUT: Mismatched state, expired timestamp ($>60$s skew), unknown JWKS `kid`, duplicate `jti`.
VALIDATION RULES: Strict cryptographic verification via RSA/ECDSA public keys from trusted JWKS.
STATE TRANSITIONS: Generates active session; records `jti` in replay cache.

## Error contract

| Code | Trigger | HTTP/status | Retryable | Client-safe message | Audit | Metric |
|---|---|---|---:|---|---:|---|
| `TOKEN_EXPIRED` | Expiration past 60s skew | 401 | no | Token has expired | yes | `identity.auth.failures` |
| `INVALID_SIGNATURE` | Bad cryptographic sig | 401 | no | Invalid token signature | yes | `identity.auth.failures` |
| `ISSUER_MISMATCH` | `iss != config.issuer` | 401 | no | Invalid token issuer | yes | `identity.auth.failures` |
| `TOKEN_REPLAY` | Duplicate JTI detected | 401 | no | Token replay rejected | yes | `identity.security.alerts` |

## Security contract

AUTHENTICATION: Establishes primary session authentication.
AUTHORIZATION: Maps external IdP claims to internal RBAC roles (`analyst`, `operator`, `tenant_admin`).
TENANT: Tenant derived strictly from tenant OIDC config and verified IdP claims.
PII: Email masked in logs (`INV-PRV-001`).
SECRET ACCESS: IdP client secret managed via `SecretReference`.
EXTERNAL ACTION: Prohibited.
DEFAULT: DENY.

## Operational behavior

RETRY: JWKS fetch retries on transient network error (max 2 retries, 500ms backoff).
TIMEOUT: JWKS HTTP request timeout 3000ms; Token validation latency $< 15\text{ms}$.
IDEMPOTENCY: JTI anti-replay cache TTL equal to remaining token lifetime.
LOGGING: Structured security event `identity.oidc.login_success` with masked email.
METRICS: `identity.oidc.auth_duration_seconds`, `identity.oidc.failures_total`.
FAILURE BEHAVIOR: JWKS outage or validation error returns 401 / fails closed.
