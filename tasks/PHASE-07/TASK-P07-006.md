## Objective and rationale

OBJECTIVE: Implement the inbound webhook receiver with HMAC-SHA256 signature verification, timestamp anti-replay protection ($\pm 300\text{s}$), transactional inbox deduplication, schema drift classification, quarantine storage, and reconciliation replay workers.
BUSINESS RATIONALE: SaaS webhooks and data feeds frequently experience signature spoofing, duplicate deliveries, out-of-order sequencing, and silent upstream schema mutations that could distort revenue metrics (`BR-004`, `INV-DATA-002`, `NFR-REL-002`).
ARCHITECTURAL OWNER: Data Platform / Integration (`revpilot.modules.connectors.ingestion`)
ARCHITECTURAL CONTEXT: Ingestion pipeline receiving push webhooks and incremental data pulls.

## Input/output and validation

INPUT: HTTP request headers, raw JSON byte stream, connector signing secret.
OUTPUT: Acknowledged `InboxReceipt` (202 Accepted) or quarantine redirection.
INVALID INPUT: Timestamp skew $> 300\text{s}$, forged HMAC signature, duplicate `(tenant_id, connector_id, external_event_id)`.
VALIDATION RULES: Constant-time HMAC comparison; max payload size 2MB.
STATE TRANSITIONS: Breaking drift transitions connector to `SCHEMA_DRIFT` and stores raw payload in `connector_quarantine`.

## Error contract

| Code | Trigger | HTTP/status | Retryable | Client-safe message | Audit | Metric |
|---|---|---|---:|---|---:|---|
| `INVALID_SIGNATURE` | HMAC signature mismatch | 401 | no | Invalid webhook signature | yes | `connectors.webhook.invalid_signatures` |
| `TIMESTAMP_SKEW` | Timestamp $> 300\text{s}$ old | 400 | no | Webhook timestamp out of bounds | yes | `connectors.webhook.timestamp_errors` |
| `PAYLOAD_TOO_LARGE` | Body $> 2\text{MB}$ | 413 | no | Webhook payload too large | yes | `connectors.webhook.size_errors` |
| `SCHEMA_DRIFT_DETECTED`| Breaking schema drift | 202 | no | Ingested to quarantine | yes | `connectors.quarantine.events` |

## Security contract

AUTHENTICATION: Webhook HMAC-SHA256 signature verification.
AUTHORIZATION: Scoped by target connector instance and tenant.
TENANT: Tenant derived strictly from target `connector_id` registration.
PII: Quarantined payloads stored encrypted at rest.
SECRET ACCESS: Webhook secrets fetched via broker.
EXTERNAL ACTION: Prohibited.
DEFAULT: DENY.

## Operational behavior

RETRY: Upstream webhooks receive 200/202 on duplicate to stop provider retry storms.
TIMEOUT: Webhook signature verification and inbox write $< 50\text{ms}$.
IDEMPOTENCY: Unique database constraint on `(tenant_id, connector_id, external_event_id)`.
LOGGING: Emits `connector.schema_drifted.v1` upon quarantine diversion.
METRICS: `connector.webhooks.received_total`, `connector.quarantine.records_active`.
FAILURE BEHAVIOR: Breaking drift isolates corrupt payloads without blocking valid transactions.
