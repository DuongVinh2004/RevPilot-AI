## Input/output and validation

INPUT: Estimated spend amount, tenant ID, dimension key, usage quantity.
OUTPUT: `SpendReservationToken` with expiration timestamp, or `UsageRecord` row.
INVALID INPUT: Negative spend amount, missing tenant ID, or reservation exceeding hard limit.
VALIDATION RULES: Atomic database serialization via `SELECT ... FOR UPDATE` row locks.
STATE TRANSITIONS: Quota transitions through `AVAILABLE` $\to$ `RESERVED` $\to$ `COMMITTED`.

## Error contract

| Code | Trigger | HTTP/status | Retryable | Client-safe message | Audit | Metric |
|---|---|---|---:|---|---:|---|
| `QUOTA_EXHAUSTED` | Spend limit exceeded | 402/429 | no | Tenant quota exceeded | yes | `finops.quota.exceeded` |
| `RESERVATION_EXPIRED` | Finalize after TTL | 409 | no | Reservation token expired | yes | `finops.reservation.expired` |
| `DUPLICATE_USAGE` | Duplicate idempotency key | 409 | no | Usage record already logged | yes | `finops.metering.duplicates` |
| `RECONCILIATION_GAP` | Invoice variance $> 2\%$ | 422 | no | Discrepancy flagged for review | yes | `finops.reconciliation.discrepancies`|

## Security contract

AUTHENTICATION: Evaluated internally on worker and API boundaries.
AUTHORIZATION: Scoped by tenant context.
TENANT: Hard tenant isolation; quotas are partitioned by `tenant_id`.
PII: Prohibited in metering dimensions.
SECRET ACCESS: Prohibited.
EXTERNAL ACTION: Governs spend limits before external actions can proceed.
DEFAULT: DENY.

## Operational behavior

RETRY: Atomic reservation retries up to 3 times on PostgreSQL serialization failure (`40001`).
TIMEOUT: Spend reservation $< 10\text{ms}$; usage record write $< 5\text{ms}$.
IDEMPOTENCY: Metering records enforced by unique database constraint on `(tenant_id, idempotency_key)`.
LOGGING: Structured FinOps event `finops.spend.reserved` and `finops.quota.exceeded`.
METRICS: `finops.quota.utilization_ratio`, `finops.spend.reserved_usd`.
FAILURE BEHAVIOR: Ambiguous quota state fails closed, blocking additional spend (`INV-REL-001`).
