## Symbol-level contract

MUST EXPORT/DEFINE:
1. `TenantQueryPort(Protocol)`:
   - `get_by_id(tenant_id: TenantId) -> Tenant | None`
   - `get_by_organization(organization_id: OrganizationId) -> list[Tenant]`
   - `get_organization_by_id(organization_id: OrganizationId) -> Organization | None`
   - `exists(tenant_id: TenantId) -> bool`
2. `TenantCommandPort(Protocol)`:
   - `save_tenant(tenant: Tenant) -> None`
   - `save_organization(organization: Organization) -> None`
   - `update_status(tenant_id: TenantId, status: TenantStatus, reason: str | None = None) -> Tenant`
3. `TenantContextPolicy`:
   - `validate_context(context: TenantContext) -> None` (fails closed if inactive or invalid)
   - `authorize_tenant_access(principal: PrincipalContext, target_tenant_id: TenantId) -> None` (enforces INV-TEN-001, INV-TEN-003)
   - `resolve_security_context(tenant: Tenant, principal: PrincipalContext) -> SecurityContext` (binds tenant context and principal context safely)

MUST NOT:
- Implement concrete persistence mechanisms (database, SQL, ORM).
- Depend on external frameworks or foreign business modules.

## Input/output and validation

- Any access across disparate tenant boundaries by a non-system principal raises `TenancyViolationError`.
- System principal (`principal.is_system == True`) is authorized across tenant boundaries.
- Attempting to authorize a non-system principal with `tenant_id == None` raises `TenancyViolationError`.
- Inactive tenant raises `TenancyViolationError` during security context resolution.
