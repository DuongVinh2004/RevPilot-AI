## Symbol-level contract

MUST EXPORT/DEFINE:

1. `PrincipalType(str, Enum)`:
   - `USER = "user"` (human interactive user)
   - `SERVICE_ACCOUNT = "service_account"` (machine-to-machine service principal)
   - `AGENT = "agent"` (delegated AI agent actor)
   - `SYSTEM = "system"` (internal platform maintenance worker)

2. `AuthTokenClaims`:
   - Immutable normalized token claims value object (`dataclass(frozen=True, slots=True)`).
   - Represents raw or deserialized claims extracted from incoming authentication assertions.
   - Attributes:
     - `sub: str` (subject principal identifier string, e.g. `usr_...` or `svc_...`)
     - `iss: str` (token issuer)
     - `aud: str` (target audience)
     - `exp: UtcDateTime` (token expiration in UTC)
     - `nbf: UtcDateTime | None = None` (not-before timestamp in UTC)
     - `iat: UtcDateTime` (issued-at timestamp in UTC)
     - `tenant_id: str | None = None` (associated tenant identifier string)
     - `roles: frozenset[str] = frozenset()` (assigned role names)
     - `permissions: frozenset[str] = frozenset()` (assigned fine-grained permissions)
     - `email: str | None = None` (user email address if human user)
     - `jti: str | None = None` (unique token identifier / replay prevention nonce)
   - **Critical Invariant**:
     - `is_system` attribute is STRICTLY PROHIBITED.
     - `AuthTokenClaims` is unverified data. It MUST NOT be accepted directly by domain factories or application use cases as authorization evidence. Primitive caller booleans (e.g. `signature_verified`, `session_active`, `token_revoked`) are NEVER trust anchors.

3. `VerifiedClaimsToken`:
   - Opaque immutable evidence object representing cryptographically verified token claims (`dataclass(frozen=True, slots=True)`).
   - Issued exclusively by the verified authentication boundary (`TokenVerificationPort`).
   - Attributes:
     - `claims: AuthTokenClaims`
     - `verified_issuer: str`
     - `verified_audience: str`
     - `session_id: str`
     - `verified_at: UtcDateTime`
     - `signature_fingerprint: str`
     - `_provenance_token: str` (internal cryptographic provenance binding)
   - Invariant: Cannot be instantiated from unverified caller payloads or without valid provenance proof.

4. `PrivilegedContext`:
   - Opaque immutable execution context for platform-level maintenance operations (`dataclass(frozen=True, slots=True)`).
   - Issued strictly at the verified platform boundary for registered platform service accounts (`INV-TEN-003`, `docs/14-iam/IAM-SPEC.md` §2.3, §3.6).
   - No public constructor for application/caller code.
   - Attributes:
     - `principal_id: PrincipalId`
     - `ticket_id: str` (emergency change / ticket identifier)
     - `justification: str` (auditable operational reason)
     - `issued_at: UtcDateTime`
     - `expires_at: UtcDateTime` (maximum lifetime: 60 minutes)
     - `_provenance_signature: str` (opaque cryptographic proof issued by platform identity authority)
   - Method: `is_valid(as_of: UtcDateTime | None = None) -> bool`

5. `Principal`:
   - Aggregate root representing authenticated actor (`dataclass(frozen=True, slots=True)`).
   - Attributes:
     - `id: PrincipalId`
     - `type: PrincipalType`
     - `tenant_id: TenantId | None`
     - `roles: frozenset[str]`
     - `permissions: frozenset[str]`
     - `is_active: bool = True`
   - Method: `has_role(role: str) -> bool` (case-insensitive role check)
   - Method: `has_permission(permission: str) -> bool` (case-insensitive permission check)
   - Method: `to_context() -> PrincipalContext`:
     - Produces standard immutable `PrincipalContext`.
     - Hardcodes `is_system=False`. Structurally prohibited from producing `is_system=True`.
     - Enforces `tenant_id is not None` for non-system actors; raises `TenancyViolationError` if `tenant_id` is missing.

6. `create_principal_from_verified_claims(verified: VerifiedClaimsToken, as_of: UtcDateTime | None = None) -> Principal`:
   - Trusted domain factory enforcing claim invariants at creation.
   - Requires strictly typed `VerifiedClaimsToken` issued by verified boundary. Rejects unverified `AuthTokenClaims` or caller booleans.
   - Revalidates time window against `as_of` (defaults to `UtcDateTime.now()`):
     - If `as_of >= verified.claims.exp + 60s`: raises `AuthenticationError("Token has expired")`.
     - If `verified.claims.nbf is not None and as_of < verified.claims.nbf - 60s`: raises `AuthenticationError("Token not yet active")`.
   - Validates `sub` parses as valid `PrincipalId` (`usr_...` or `svc_...`).
   - Enforces `INV-TEN-003`: Non-system principal MUST have a valid `tenant_id`. If `verified.claims.tenant_id is None`, raises `TenancyViolationError("Principal lacks required tenant association")`.
   - Validates `tenant_id` parses as valid `TenantId`.
   - Determines `PrincipalType`: `SERVICE_ACCOUNT` if registered machine prefix (`svc_...`), else `USER`. NEVER assigns `SYSTEM` to token-authenticated actors.

7. `TokenVerificationPort(Protocol)`:
   - Minimal boundary interface defining verification contract:
     ```python
     class TokenVerificationPort(Protocol):
         def verify_token(
             self,
             token_string: str,
             *,
             expected_issuer: str = "revpilot-idp",
             expected_audience: str = "revpilot-api",
             as_of: UtcDateTime | None = None,
         ) -> VerifiedClaimsToken:
             """
             Cryptographically verifies token signature, issuer, audience,
             clock skew bounds (60s), active session, revocation list, and anti-replay (JTI).
             Returns trusted VerifiedClaimsToken or raises AuthenticationError / TenancyViolationError.
             """
             ...
     ```

MUST NOT:
- Accept caller-supplied boolean flags (e.g. `is_system`, `signature_verified`, `session_active`, `token_revoked`) as trust anchors.
- Accept raw or unverified `AuthTokenClaims` into domain entity factories.
- Expose a public constructor for `PrivilegedContext`.
- Allow `Principal.to_context()` to manufacture `is_system=True`.
- Implement password hashing, raw password storage, or secret token storage (`INV-SEC-001`).
- Call external identity providers, OAuth2 servers, LDAP, or network APIs.

## Input/output and validation

- `sub` cannot be empty or whitespace; must parse as valid `PrincipalId` with prefix `usr_` or `svc_`.
- `exp`, `iat`, and `nbf` must be valid timezone-aware `UtcDateTime` instances; naive datetimes are rejected with `TypeError` or `ValueError`.
- Clock skew tolerance is strictly 60 seconds (`docs/14-iam/IAM-SPEC.md` §2.3).
- Token issuer must match expected issuer; audience must match platform audience (`revpilot-api`).
- Non-system principal requires explicit tenant claim (`INV-TEN-003`).
- Malformed tenant claim raises `ValidationError` or `TenancyViolationError`.
- Missing required token attributes raises `ValidationError`.

## Security contract

- Invariant `INV-IAM-001`: Deny-by-default server-side verification at every capability boundary.
- Invariant `INV-TEN-002`: Principal and tenant context derived strictly from verified claims, never client override.
- Invariant `INV-TEN-003`: System privilege requires explicit verified platform boundary and opaque `PrivilegedContext`; non-system actors cannot have null tenant.
- Invariant `INV-SEC-001`: No credentials or secrets stored or logged.
- Invariant `INV-REL-001`: Identity/policy uncertainty fails closed.

## Tenancy contract

- Non-system principal requires explicit tenant claim (`INV-TEN-003`).
- Malformed tenant claim raises `ValidationError` or `TenancyViolationError`.
- System principal paths explicit via opaque `PrivilegedContext`; cannot forge tenant bypass.
