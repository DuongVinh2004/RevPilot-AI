## Symbol-level contract

MUST EXPORT/DEFINE:
1. `RLSViolationError(Exception)`:
   - Exception representing Row-Level Security policy or context failure.
2. `RLSSessionConfig`:
   - Value object generating parameterized SQL statements for session isolation:
     - `get_set_tenant_sql(tenant_id: TenantId) -> tuple[str, tuple[str, ...]]`:
       - Returns `("SET LOCAL revpilot.current_tenant_id = %s; SET LOCAL revpilot.is_system = 'false';", (str(tenant_id),))`
     - `get_set_system_sql() -> str`:
       - Returns `"SET LOCAL revpilot.current_tenant_id = ''; SET LOCAL revpilot.is_system = 'true';"`
     - `get_reset_sql() -> str`:
       - Returns `"RESET revpilot.current_tenant_id; RESET revpilot.is_system;"`
     - `get_verify_sql() -> str`:
       - Returns `"SELECT current_setting('revpilot.current_tenant_id', true), current_setting('revpilot.is_system', true);"`
3. `DatabaseSessionBoundary`:
   - Context manager managing connection transaction lifecycle:
     - Accepts `connection: Any`, `context: TenantContext | None = None`.
     - `__enter__()`:
       - If `context is None`: raises `TenancyViolationError("Cannot establish database session without TenantContext")`.
       - If `context.is_system`: executes `get_set_system_sql()`.
       - If non-system: executes `get_set_tenant_sql(context.tenant_id)`.
       - Returns connection.
     - `__exit__(exc_type, exc_val, exc_tb)`:
       - Executes `get_reset_sql()`.

MUST NOT:
- Permit database session establishment with `context = None`.
- Permit string concatenation of `tenant_id` into SQL statements (must use parameterized query tuples).
- Allow persistent connection state leakage.

## Input/output and validation

- Parameterized SQL tuples must be used to prevent SQL injection.
- Rejects non-system context without tenant identifier.
- Cleans up session variables in `__exit__`.
