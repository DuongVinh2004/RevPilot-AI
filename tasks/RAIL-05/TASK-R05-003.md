## Symbol-level contract

MUST EXPORT/DEFINE:
1. `MigrationSafetyValidator`:
   - Class validating DDL statements against expand/contract rules:
     - `validate_ddl(ddl_statement: str) -> None`:
       - Raises `ValidationError("Destructive column drop prohibited without deprecation release")` if `DROP COLUMN` is detected.
       - Raises `ValidationError("Direct column rename prohibited; use expand/contract dual writing")` if `RENAME COLUMN` is detected.
       - Raises `ValidationError("Adding NOT NULL column without DEFAULT is prohibited")` if `ADD COLUMN ... NOT NULL` without `DEFAULT` is detected.
       - Raises `ValidationError("Dropping table prohibited without authorization")` if `DROP TABLE` is detected.
2. `IsolatedTenantRepositoryAdapter(TenantScopedRepositoryPort[Tenant])`:
   - Concrete repository adapter simulating RLS-enforced database storage:
     - Implements `get_by_id(context: TenantContext, id: str) -> Tenant | None`
     - Implements `save(context: TenantContext, entity: Tenant) -> None`
     - Implements `delete(context: TenantContext, id: str) -> None`
     - Implements `list_by_tenant(context: TenantContext, limit: int = 100, offset: int = 0) -> Sequence[Tenant]`
   - Internal storage partitioned by `tenant_id`.
   - Simulates RLS: Enforces that queries executed without valid context or with mismatched context fail closed (`TenancyViolationError`).

MUST NOT:
- Allow unvalidated DDL statements to pass `MigrationSafetyValidator`.
- Allow repository access without verifying `TenantContext`.
- Return data across tenant partitions.

## Input/output and validation

- DDL string must be parsed case-insensitively for prohibited operations.
- Repository operations strictly validate `context.is_active` or `context.is_system`.
